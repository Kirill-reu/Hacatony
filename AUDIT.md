# Аудит

Два разных смысла слова "аудит" в этом репозитории — не путать:

1. **Аудит сгенерированных слайдов** (ТЗ §2.6 + Приложение 1) — часть
   пайплайна генерации, реализована в `app/pipeline/audit.py`, прогоняется
   автоматически на каждом собранном `.pptx` и попадает в ответ `/jobs/{id}`
   как список найденных проблем.
2. **Тесты кода** (`pytest`) — обычные unit/integration тесты самого
   сервиса, в `tests/`.

## 1. Аудит презентаций (`app/pipeline/audit.py`)

Ровно по чек-листу Приложения 1 ТЗ, разделён на два рода проверок:

### Детерминированные (`run_deterministic_audit`)

Один и тот же слайд всегда даёт один и тот же результат — считаются прямо
из геометрии и XML собранного `.pptx`, без модели.

| Категория (Приложение 1) | Код | Что проверяет |
|---|---|---|
| Вёрстка | `out_of_bounds` | элемент вышел за границы слайда |
| Вёрстка | `overlap` | два элемента заметно перекрываются (>10% площади меньшего) |
| Вёрстка | `picture_stretched` | пропорции изображения нарушены |
| Шаблон | `font_not_in_theme` | шрифт не из темы шаблона |
| Шаблон | `size_not_in_scale` | кегль вне типографической шкалы шаблона |
| Шаблон | `color_not_in_palette` | цвет текста вне палитры шаблона |
| Шаблон | `low_contrast` | контраст текста к фону ниже 4.5:1 (формула WCAG) |
| Плотность | `too_many_bullets` | больше 6 буллетов на слайде |
| Плотность | `bullet_too_long` | буллет длиннее 15 слов |
| Плотность | `table_too_many_rows` / `table_too_many_cols` | таблица больше 7 строк / 5 колонок |
| Плотность | `chart_too_many_series` | больше 5 серий на диаграмме |
| Плотность | `underfilled` / `overfilled` | слайд заполнен <25% или >75% площади |
| Целостность | `leftover_placeholder` | текст-заглушка (lorem ipsum, TODO, XXX, "вставьте текст") |
| Целостность | `empty_slide` | слайд пустой или только заголовок |
| Целостность | `chart_missing_legend` | у диаграммы нет легенды (для многокатегорийных) |
| Целостность | `duplicate_slide` | два слайда дублируют друг друга (по нормализованному тексту) |

Не перенесены в код дословно из Приложения 1 (геометрически не различимы
средствами `python-pptx` без рендеринга в растр — например "текст обрезан
краем слайда" при включённом автоуменьшении шрифта, или "блоки не
выровнены по направляющим макета", для чего нужны сами направляющие, а не
только геометрия плейсхолдеров): помечено как открытый пункт для расширения
чек-листа, как и разрешает сам ТЗ ("его можно расширять и сокращать с
обоснованием").

### Контекстные / недетерминированные (`run_content_audit`)

Выполняются моделью (`LLMClient.complete_json`) на текстовом содержимом
каждого слайда — на повторном прогоне могут дать другой результат, это
свойство самой проверки, а не баг:

- заголовок содержит вывод, а не просто называет тему;
- содержимое слайда соответствует заголовку;
- на слайде есть содержание, а не только заголовок;
- нет служебного мусора (реплик спикера, кусков промпта);
- текст без опечаток;
- все цифры и факты со слайда есть в переданном списке фактов.

Без настроенной `LLM_BASE_URL` эта часть тихо пропускается (лог-уровня
`info`, не ошибка) — детерминированная часть аудита всё равно отрабатывает
полностью.

### Где это видно в API

`GET /jobs/{job_id}` → `variants[].audit`: список `issues` (`slide_index`,
`category`, `code`, `message`, `deterministic`, `severity`) +
агрегаты `deterministic_issue_count`/`content_issue_count` — то самое
"пользователь выбирает, какие из них исправить" из ТЗ (решение, что делать
со списком проблем, — за фронтендом/пользователем, backend только считает
и отдаёт).

## 2. Тесты кода (`pytest -q`, `tests/`)

| Файл | Покрытие |
|---|---|
| `test_template_parser.py` | Извлечение цветов темы и шрифтов; валидный hex; классификация всех стандартных ролей макета (`title_slide`, `content_bullets`, `two_content`, `content_image`, `section_header`) на предсказуемо структурированном .pptx; типографическая шкала непустая и отсортирована; фолбэк `best_layout_for` на отсутствующую роль; отступы в границах слайда |
| `test_audit.py` | По одному тесту на каждый проверяемый детерминированный код: `out_of_bounds`, `overlap`, `too_many_bullets`, `leftover_placeholder`, `empty_slide`, `duplicate_slide`; плюс контрольный тест, что аккуратный слайд не даёт ни одной проблемы (нет ложных срабатываний) |
| `test_pipeline_integration.py` | Сквозной прогон всего пайплайна на офлайн-заглушках (`OfflineStubClient` + `PlaceholderImageClient`, без сети/ключей): генерируются все 3 варианта, файлы `.pptx`/`.html` реально создаются, варианты действительно различимы (по числу слов и/или числу фигур — не идентичны); отдельный тест на остановку по бюджету времени (`deadline_ts` в прошлом → 0 вариантов вместо падения) |

Список тестов сознательно не дублирует детерминированный аудит презентаций
один в один (не каждый код аудита имеет отдельный юнит-тест) — покрыты
самые частые/показательные случаи из каждой категории Приложения 1;
остальные коды используют ту же проверенную геометрическую логику
(`_bbox`/`_overlap_area`/`_contrast_ratio`), так что риск отдельной ошибки в
непокрытых прямым тестом кодах низкий, а не нулевой — это баланс, а не
полное покрытие.

Все тесты — без сети и без ключей API, воспроизводимы в любом CI.
