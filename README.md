# Цифровой дизайнер презентаций — backend

Backend для VK Tech хакатон-кейса: сервис генерирует презентацию на основе
загруженного пользователем `.pptx`-шаблона и краткого брифа, разбирая шаблон
на дизайн-систему и собирая **3 различимых варианта** верстки с автогенерацией
текста, изображений, таблиц и графиков. Экспорт — в `.pptx`, `.pdf`, `.html`.

Это только backend — FastAPI-сервис без UI. Frontend будет отдельным
модулем и общается с этим сервисом по HTTP.

Как это соответствует ТЗ и что где искать — см. [ARCHITECTURE.md](ARCHITECTURE.md).
Использованные модели — [MODELS.md](MODELS.md). Аудит и тесты — [AUDIT.md](AUDIT.md).

## Быстрый старт

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить при необходимости, см. ниже
uvicorn app.main:app --reload --port 8000
```

Открыть `http://localhost:8000/docs` — там весь API в Swagger UI.

## Переменные окружения

Полный список с комментариями — в `.env.example`. Всё имеет рабочий дефолт,
сервис запускается вообще без `.env` (см. "Запуск без API-ключей" ниже).
Ключевые группы:

| Группа | Переменные | Что делают |
|---|---|---|
| Хранилище | `APP_DATA_DIR` | Где лежат загруженные шаблоны и результаты задач |
| Лимиты генерации | `MAX_GENERATION_SECONDS`, `DEFAULT_SLIDE_COUNT`, `MIN_SLIDE_COUNT`, `MAX_SLIDE_COUNT`, `VARIANT_COUNT` | Бюджет времени на задачу и границы числа слайдов |
| Текстовая LLM | `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_TIMEOUT_SECONDS` | Любой OpenAI-совместимый `/chat/completions` |
| Text-to-image | `IMAGE_BASE_URL`, `IMAGE_API_KEY`, `IMAGE_MODEL` | Любой OpenAI-совместимый `/images/generations` |
| Веб-поиск фактов | `WEB_SEARCH_ENABLED`, `WEB_SEARCH_MAX_RESULTS` | Обоснование цифр на слайдах, ключ API не нужен |
| Экспорт | `SOFFICE_BINARY`, `PDF_EXPORT_ENABLED`, `PDF_EXPORT_TIMEOUT_SECONDS` | PDF через LibreOffice headless |
| API | `CORS_ORIGINS` | Для похода с фронтенда из браузера |

## Запуск без каких-либо API-ключей

Сервис специально спроектирован так, чтобы **полностью работать без единого
ключа** — это фолбэк-режим для разработки/CI, а не заглушка "для галочки":

- без `LLM_BASE_URL` — включается `OfflineStubClient`, а генератор контента
  строит план детерминированно из предложений брифа и найденных фактов;
- без `IMAGE_BASE_URL` — вместо картинки от text-to-image модели вставляется
  сгенерированная PIL-плашка-заглушка с текстом промпта;
- без `soffice` в PATH — экспорт в PDF просто пропускается (в логе
  предупреждение), `.pptx`/`.html` всё равно собираются.

Перед демо/защитой — задать в `.env` реальные `LLM_BASE_URL`/`IMAGE_BASE_URL`
(подробности и требования ТЗ к моделям — в [MODELS.md](MODELS.md)).

Для PDF-экспорта нужен LibreOffice: `sudo apt install libreoffice`.

## API

- `POST /templates` — `multipart/form-data`, поле `file` — `.pptx`.
  Возвращает `template_id` и разобранную дизайн-систему (палитра, шрифты,
  типографическая шкала, макеты и их роли).
- `POST /generate` — `{"template_id", "brief", "purpose", "slide_count"?,
  "language"?, "audience"?}`. Возвращает `job_id`, генерация идёт в фоне.
- `GET /jobs/{job_id}` — статус (`queued|running|done|failed|timed_out`),
  прогресс, а после готовности — 3 варианта со ссылками на файлы и отчётом
  аудита (список найденных проблем с пометкой детерминированная/контентная).
- `GET /jobs/{job_id}/download/{variant_id}/{pptx|pdf|html}` — сам файл.

Пример:

```bash
curl -F "file=@template.pptx" http://localhost:8000/templates
curl -X POST http://localhost:8000/generate -H "Content-Type: application/json" -d '{
  "template_id": "...",
  "brief": "Запускаем фичу X для команды Y: что это, зачем, как работает",
  "purpose": "feature",
  "slide_count": 12
}'
curl http://localhost:8000/jobs/<job_id>
```

## Ограничения и осознанные компромиссы

- **SmartArt** в OOXML — проприетарный формат, `python-pptx` его не создаёт
  и не читает. "SmartArt-подобный" элемент — это ряд скруглённых
  прямоугольников + коннекторы (нативные фигуры, не растровая картинка).
- **HTML-экспорт графиков** — рендерятся PNG-снэпшотом (matplotlib) из тех
  же данных, что и нативный `.pptx`-график, а не воспроизводятся средствами
  браузера — сознательный компромисс, чтобы HTML оставался самодостаточным
  файлом без внешних JS-библиотек. Текст, таблицы и картинки в HTML — не
  растровые, остаются настоящей разметкой (подробнее в ARCHITECTURE.md).
- **Бюджет времени**: `MAX_GENERATION_SECONDS` (по умолчанию 280с) — это
  бюджет на всю задачу (3 варианта), не на один вариант; при нехватке
  времени сервис возвращает уже готовые варианты вместо падения (статус
  задачи — `timed_out`, а не `failed`).
- **Хранилище задач** — in-memory (`app/storage.py: JobStore`) + файлы на
  диске. Достаточно для хакатона/однопроцессного демо; для продакшена —
  заменить на Redis/БД и S3-совместимое хранилище (единая точка расширения
  — вызовы `storage.py` больше нигде не разбросаны).
- **Только backend**: авторизации, rate limiting и персистентной БД
  сознательно нет — не требовалось для отборочного этапа.

  `visual_generator.py` в отдельные версионируемые файлы (ТЗ §2.4).
